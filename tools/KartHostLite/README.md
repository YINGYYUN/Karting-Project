# KartHostLite — 卡丁快跑 轻量上位机

从队友 `KartHost`（11.5k 行）里**只搬基础功能**：收帧 → 画波形 → 调参数 → 录 CSV。
不含惯导/路表/标定窗/模拟车端/串口链路。

> 本项目由我与队友 **zjc** 合作完成，他的仓库：
> **[hz303/zjc_kart_cyt4bb7](https://github.com/hz303/zjc_kart_cyt4bb7)**。

## 为什么是这套技术栈

- 队友的 `Protocol.cs` / `FrameParser.cs` / `Link.cs` / `ChannelStore.cs` /
  `CsvRecorder.cs` / `Ui/WavePanel.cs` / `Ui/ParamPanel.cs` 已经解决了最难的两件事：
  **30 FPS 重绘与接收解耦**、**半包/垃圾字节/坏 CRC 下的帧同步**。自己重写等于重踩一遍。
- 因此这些文件是**原样搬过来的**（`namespace KartHost` 保持不变，`RootNamespace` 也设为 `KartHost`，
  一个字符都不用改）。本工程新写的只有 8 个文件：

| 文件 | 作用 |
|---|---|
| `Channels.cs` | ★ 通道表：**两套档案**（全量 41 / 标定 18），每套 4 张平行数组（英文名 / 单位 / 中文简称 / 悬停说明）+ 分图预设 + 实时值格子 + 轨迹通道 ——「用哪套档案」的唯一落点 |
| `Ui/MainForm.cs` | 主窗（左参数 / 中波形或轨迹 / 右实时值+通道显隐 / 底部日志+状态栏） |
| `Ui/TrackPanel.cs` | odom 轨迹图（只读，x 横轴 / -y 纵轴，等比 1:1、清空、暂停） |
| `RouteLink.cs` | ★ 路表**串口灌表**链路（DAP 虚拟串口；协议与车端 `route_link.c` 逐字节对应） |
| `RouteImage.cs` | 车端路表镜像（`route_car.bin`）的生成 / 校验；能造圆环、直线测试表 |
| `Ui/RouteForm.cs` | 路表面板（选串口 / 灌表 / 读回 / 槽位一览） |
| `SelfTest.cs` | 无硬件自检（协议层 + 两套通道表 + 路表镜像与帧） |
| `Program.cs` | 入口 + `--selftest` / `--shot-form` / `--shot-demo` / `--shot-route` / 路表命令行 |

从队友那份搬来的文件共 10 个（含 `Ui/LampControl.cs` 指示灯）：`Protocol` `FrameParser` `Link`

点「轨迹图」把中间那块换成 odom 轨迹（x 横轴 / **-y** 纵轴，车头朝上，等比 1:1 可关），
再点一次回到波形。轨迹图是**只读**视图：清空只清本机显示，不动数据、不发任何下行命令。

三条**改界面时必须遵守**的规矩（都是踩过的）：

1. **字号写 9pt，不要乘 `Dpi.Scale`**（点值是物理量，GDI+ 自己会放大）。之前写成 `Dpi.Pxf(9f)`，
   150% 下变 13.5pt，整窗大一圈 —— 就是这次改版要修的观感问题。
2. **通道勾选框的字色必须在 `Theme.Apply()` 之后再刷一遍**：它会把所有 `CheckBox.ForeColor`
   统一成 `Theme.Text`，先设就全白，曲线颜色和图例对不上。
3. **多图模式下，勾完默认通道要再套一次分图预设**：勾选会把通道塞进每一张图，
   不补这一步四张图会长得一模一样。

| 开发调试版 | `bin\Debug\net9.0-windows\KartHostLite.exe` | ⚠ **不要双击**。它是 apphost，只会去 `C:\Program Files\dotnet` 找 9.0 运行时，本机只有 8.0.31 → 弹 "You must install or update .NET"。用 `run.bat` 启动 |
| 命令行 / 自检 | `run.bat`、`run.bat --selftest` | 有 `dist` 就跑 `dist`，没有就用私有 SDK 的 `dotnet.exe` 跑 `bin\...\KartHostLite.dll` |

```bat
build.bat            :: Debug 构建（→ bin\Debug\net9.0-windows\）
publish.bat          :: 生成免安装单文件（→ dist\KartHostLite.exe，113 MB）
run.bat              :: 启动界面
run.bat --selftest   :: 无硬件自检（退出码 = 失败项数）
```

`build.bat` / `run.bat` / `publish.bat` 找 dotnet 的顺序：环境变量 `DOTNET` → 私有路径 → PATH 里的 `dotnet`。
换机器时把 `DOTNET` 指过去即可（只有构建/发布需要，跑 `dist` 版不需要）。

⚠ **三个 .bat 必须保持纯 ASCII**：cmd 用 GBK 解码，文件里的中文会让解析错位，
症状是 `'ET_CLI_TELEMETRY_OPTOUT' 不是内部或外部命令` 这种莫名其妙的截断报错。

## 用法（车端是 UDP 客户端）

1. 车端进 Host 页（会自动弹 WiFi 选择界面，连上才开始发）。
2. 本机：填 **本机 UDP 端口 8086** → 点「开始接收」。**不是"去连车"** —— 车端主动发到本机这个端口。
3. 左侧勾选要画的通道；中间波形；右侧参数滑条（滑条一动就下发 `SET_PARAM`）。
4. 「存 Flash / 读 Flash」= `SAVE / LOAD` 命令。
5. 「录制 CSV」= 按 20 ms 周期把勾选通道写盘；「导出」= 把缓冲里**已经收到**的那一段倒成 CSV。

⚠ **防火墙**：首次运行 Windows 会问是否允许网络访问，必须允许，否则收不到 UDP。

## CSV：两条路，同一套格式（2026-10-24 与队友对齐）

| | 「录制 CSV」（`CsvRecorder`） | 「导出」（`CsvExport`） |
|---|---|---|
| 方向 | **从现在起往后记** | 把缓冲里**已经收到**的倒出来（每通道 6000 点环形） |
| 用途 | 已经知道要做什么实验 | 事后才想起来要看数字；屏幕上波形长什么样，导出来就是什么样 |
| 采样 | 20 ms 抽稀（独立 **10 ms** 定时器驱动） | 缓冲里的原始点，一个不少 |
| note 列 | 可写锚点（阶跃标记用） | 恒为空 |

两种文件的表头**逐字节相同**：

```
t_ms,note,<通道名>[<单位>],<通道名>[<单位>],...
```

- UTF-8 **带 BOM**（Excel 双击打开不乱码）；数值 `InvariantCulture` + `0.######`。
- 空值写**空字符串**而不是 `NaN`（Excel 会把 `NaN` 当文本，整列变字符串）。
- 通道**按通道号升序**排列，与勾选顺序无关；`t_ms` 从 0 开始（减掉第一点）。
- 两条路的时间轴不同：录制用 `Environment.TickCount64`（毫秒，与采样周期同一根）；
  导出用 `ChannelStore` 里那条 PC 时钟（秒，与波形同步）。**换算在各自内部完成，不要在外面混用。**

> 2026-10-24 修：原来 `_rec.Tick/Start` 传的是 `_sw.Elapsed.TotalSeconds`（秒），而
> `CsvRecorder` 的抽稀是 `_next += periodMs`（毫秒）—— 结果两次落盘之间隔 20 **秒**，
> 录出来几乎是空表。现在统一走 `NowMs()`，并把采样从 30 FPS 重绘定时器挪到独立的 10 ms 定时器。

## 与车端的协议约定（`Host_Ctrl.c` 那一侧）

- 上行 `A5 5A | TYPE | LEN | PAYLOAD | CRC16 | 00 00 80 7F`；CRC16-MODBUS(0xA001)，全小端。
- 遥测载荷 `SEQ(2) + TS(2→4) + MASK(2) + COUNT(2) + float32×N`；`MASK=0xFFFF` 是「全部有效」哨兵。
- 下行固定 15 字节 `5A A5 | 01 | 08 00 | CMD | ID | VALUE4 | TOKEN2 | CRC2`。
- **通道数由帧内 `COUNT` 自描述**。2026-10-22 起车端有两套档案，**按 COUNT 自动选**：

  | COUNT | 档案 | 来源 | 帧长 |
  |---|---|---|---|
  | 41 | 「卡丁·全量41」（默认，车端 `tel_sel = 0`） | 队友 `motor_link.h` 的 `CH_*` | 185 B |
  | 18 | 「卡丁·标定18」（车端 `tel_sel = 1`） | 队友 `motor_link.h` 的 `CT_*` | 93 B |

  其它 COUNT 一律**丢帧**并在状态栏提示 —— 绝不"猜一个最接近的档案"套名字（会把数据标错名且不报错）。
  切换档案时本机会自动清空数据、重建勾选列表与实时值格子，**正在录制则停掉 CSV**（两种列义不能混一个文件）。
- `Channels.cs` 里每套档案是**四份平行数组**：`Names`（英文，CSV 表头/波形图例用）、`Units`、
  `Cn`（中文简称，右侧勾选列表用，显示宽度控制在 12 个半角单位内）、`Tips`（悬停说明）。
  四份长度由 `--selftest` 强制对齐；中文简称超宽也会被自检拦下来（WinForms 裁字是不报错的）。
- ⚠ `u_l / u_r / uff_l / uff_r` 车端发的是**百分数**（车端已把归一化 ±1 乘了 100），
  所以单位是 `%`、满占空比约 ±50 —— **不要当 ±1 画**，否则看起来像"没出力"。
- odom 轨迹图用全量档案的 `ins_x(29)` / `ins_y(30)`；标定档没有这两路，轨迹图显示 **N/A**。

## 路表 · 串口灌表（2026-10-23 新增）

**为什么是串口不是 WiFi**：车端 WiFi 下行是**定长 15 B**（`HOST_DN_FRAME_LEN`），一张表 32 KB
要改下行协议核心 + 自己做分片重传；串口是自己的字节流，一层都没有。
所以这条路走 **DAP 自带的虚拟串口**（车端 `UART_0`，115200，与 `printf` 日志共用一根线）。

- 主窗右上角 **「路表…」** 打开面板：选串口 → 打开 → 握手 PING → 选镜像 / 造测试表 → 灌表。
- ★★ **车端必须停在【参数页】（主菜单 → Param）**。车端的分步写盘只在
  `Param_Page.c` 的 `param_page_loop()` 里推进（`route_link_tick()` 的唯一调用点）。
  停在别的页面：收不到帧、也写不完 Flash（**数据不丢**，回到参数页继续），但上位机会先 25 s 超时。
- **槽的纪律**：槽 0 是"手推录制"的家，面板里就没有 0，车端协议层也会拒。
- **传输期间车端日志会静音**（`debug_uart_mute`），这是有意的 —— 文本插进二进制帧会破坏帧同步。
- 影像格式：`36 B 头 + N×16 B 记录`，`magic="CTRK"`、`ver=2`、两个 CRC16-MODBUS。

### 路表管理器（2026-10-24 扩充：A 表格/校验/预览 + B 复制/设当前）

面板已从"能灌能读"扩成**管理器**，主窗右上角「路表…」打开：

| 功能 | 说明 |
|---|---|
| **槽位表格** | 槽 / 有效 / 点数 / 里程 m / ds mm / 记录 CRC / 当前（★）。当前槽用强调色标出来，空槽灰显 |
| **读回并校验** | 从**选中的那一行**读回（双击行也等于读回），读完**当场**跑 `VerifyImage`：两个 CRC + 长度自洽 ⇒ 绿的"✓ 校验通过"或红的"✗ 原因" |
| **交叉核对** | 读回的点数 / ds 与槽位表报的元数据**比对**，不一致会打 ⚠（说明读回丢块或车端槽头坏了） |
| **轨迹预览** | 右侧等比例图（不拉伸），绿点 = 起点、红点 = 终点，右下角标范围。数据来自读回的镜像（或本地镜像） |
| **设为当前槽** | `SLOT_SEL persist=1 load=1` —— 写进槽索引，重启后仍是它 |
| **槽间复制** | 把**刚读回的那张**原样灌到另一个槽（复制前再验一次 CRC，坏表拒绝复制；覆盖前有确认框） |
| 保存读回镜像 | 命名 `route_slot<槽>_<时分秒>.bin` |

> 为什么"读回后必须校验"：`SLOT_READ` 是分块拉的（512 B/帧 + 重试），理论上可能丢块。
> 只把字节存成 .bin 而不校验，会得到"看起来正常的坏表"—— 回放时表现为莫名其妙跑飞。

### 路表体检（`RouteAudit.cs`，2026-10-24）

读回 / 校验镜像后**自动跑一遍几何体检**，日志里逐项给「实测」+「建议」，可「导出体检报告…」（`.txt`）。
命令行也能单独跑：`KartHostLite --audit <镜像.bin> [报告.txt]`（**退出码 0 = 通过 / 2 = 不过**，可脚本化）。

| 检查项 | 实测给什么 | 建议值（出处） |
|---|---|---|
| 采样点距 | 均值 / σ / min / max | σ ≤ 10% × ds |
| **最小半径** | 数值 + **第几点** + 该点坐标 | ≥ **1.30 m**（= `L/tan(27°)` = 0.66/0.510，`PB_L_DEFAULT`/`PB_DELTA_MAX`） |
| 允许最高车速 | √(alat/κ_max) | 巡航 `pb_v` ≤ 该值；或 `pb_ve=1` 让弯道自动降速 |
| 侧向加速度 | 表内速度下的 v²κ 峰值 + 第几点 | ≤ **2.00 m/s²**（`PB_ALAT_DEFAULT`） |
| 闭合误差 | 末点到起点的距离 | ≤ 0.30 m |
| 单点航向变化 | 最大 \|Δyaw\| + 第几点 | ≤ 20°（超过通常是跳点/丢点） |
| **航向口径** | 表内 yaw 与"相邻点方向"的平均差 | ≤ 30°（≈90° 说明 yaw 不是车头朝向） |
| 倒车段 | 段数与点数区间 | 正车回放应为「无」 |
| 打角字段 | steer 的范围 / 是否常量 | 逐点打角要求 steer 有效 |

曲率用**和车端 `pb_speed_limit()` 完全相同的窗口与公式**（±`PB_KWIN` 点、弧长累加、首尾 yaw 差），
所以「允许最高车速」就是车上会算出来的那个数 —— 不是另算一套近似值。

### 倒车段回放（2026-10-24，车端 `route_pb.c`）

**存储结构没变**：表里本来就有 `v_cmps`（有符号，<0 = 倒车）、`steer_cdeg`、`flags` bit2 `INS_WP_FL_REV`，
以前回放一个都没读。现在按四条规则用起来：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | `s_rev` = REV 位优先、`v < −0.10` 兜底（同一拍 `p[best]`） | 录制侧打位门限是 −0.02，回放侧 −0.10 更稳；两个判据都吃 |
| 2 | 倒车段：**速度 = 表里负值**（被 `|pb_v|` 与 `PB_REV_VMAX=0.60` 封顶） | 录制多快就倒多快；纯跟踪的曲率限速对倒车无意义 |
| 3 | 倒车段：**关航向外环 + 开环回放录制打角** | `α` 与 `δ=−kp·err` 都按"车头朝前"推导，倒车时前进点落在车后（实测 α≈−178°）⇒ 继续闭环就满舵打转 |
| 4 | 到换向点的**剩余弧长 < 一个前视**时，也用录制打角 | 否则前视点会越进"倒回来的那条腿"，25~29 点被指令成满舵（录制只有 +13°） |
| 5 | **按表尾状态定收尾策略**：表尾是倒车段 ⇒ 先刹停再收（后轮使能+目标 0、舵机保持不回正，`|v| ≤ 0.06` 或 1.5 s 超时才算完）；表尾是前进段 ⇒ 到点即收 | 车到终点还在往后滑时，直接 `pb_finish()`（放开电机=自由轮、舵机回正）会让车继续退、方向盘突然自己回正 |
| 附加 | 换向前一点压到 `PB_REV_CREEP=0.15 m/s` | 实测表 29→30 只有 4 mm，不减速会卡进度点、速度反向冲击大 |

> **表尾状态怎么读**：不能只看末点 —— 录制器停止时会补一个 `v=0` 的收尾点（实测表最后一点就没有 REV 位）。
> 判据是**最后 `PB_TAIL_N(3)` 个点里多数是倒车点**。倒车→前进的过渡（表中间那种）也复用同一套刹停原语：
> 车还在往后滑时不许开航向环（`δ=−kp·err` 差个符号就是正反馈）。

**离线推演器**（不用上车）：`KartHostLite --sim <镜像.bin> [pb_v] [ld]`
逐点算出「旧逻辑 vs 新逻辑」那一拍会下发的 `v / δ` 并与录制打角对比。
⚠ 它不是动力学仿真（没有轮胎/舵机延迟），只验证"指令本身合不合理"，这正是出问题的地方。

实测那张含倒车段的表（58 点，倒车 27 点占 47%）：

| | 满舵点数 | 正车段与录制打角最大差 |
|---|---|---|
| 旧逻辑（不认倒车段） | **34** | 40.6° |
| 新逻辑 | **3**（就是那个 R≈1.27 m 的弯，物理上就要 27.6°） | 23.1°（`ld=0.8`）／**14.9°（`ld=0.40`）** |

### 车端与路表/回放有关的参数（2026-10-23 起）

| 参数 | ID | 作用 |
|---|---|---|
| `rt_ept` | 16 | **停止录制时强制补最后一个点**（默认 1）。采样按里程触发，按下停止如果还没走够一个点距，末尾那一段会整段没有点；而终点往往正打着大角 —— 少这一点，回放末尾既没位置也没正确打角。只在"位置没动且打角没变"时才不补。 |
| `pb_L` | 17 | **有效轴距 L**（默认 0.66 m）。回放的 `k = 2L/ld` 与 `δ = atan(L·κ)` 都用它；原来写死在 `route_pb.h`，换车要重编译。 |
| `pb_ve` | 18 | **速度剖面开关**（默认 0 = 关）。置 1 后 `pb_v` 从"恒定车速"变成"车速上限"，实际速度由下面两项决定。关着时行为与以前**完全一样**。 |
| `pb_alat` | 19 | 允许的**横向加速度**（默认 2.0 m/s²）。弯道限速 `v ≤ √(alat/κ)`，κ 越大能跑越低。调大 = 更凶，会先推头。 |
| `pb_vmin` | 20 | 弯道限速的**地板**（默认 0.30 m/s）。低于电机死区会一走一停。 |
| `pb_kh` | 21 | **航向增益手工覆盖**（默认 0 = 自动按 `2L/ld`）。只有做 A/B 时才填；把它写死成常数会让这个环的特征频率随前视漂移（队友那边"head_kp 写死就振"就是这个原因）。 |
| `rt_rrec` | 22 | **倒车录表**（默认 0）。置 1 后录制时把 `v` 存成 `|v|`（REV 位照打）—— 这张表此后专用于"正车倒序回放"。 |
| `rt_rply` | 23 | **倒序回放**（默认 0）。置 1 时起跑会把点序**原地倒过来**，车**正着**开回起点。与表的出身不一致会**拒绝起跑**并显示原因（`not rev table` / `need RevPlay`）。 |

> 2026-10-24 补：`Motor_Diff_Alloc()` 的轴距改成**由调用方传入**（两个调用点都传 `pb_L`）。
> 以前这里内用宏 `MOTOR_DIFF_L = 0.66`，而回放的 `2L/ld` 用参数，**改一个另一个不动** ——
> 现在轴距只有一个来源。

`pb_ve = 1` 时另有一个**固定末段收油**：离末点越近，上限按 `√(creep² + 2·alat·d)` 收紧，
最后一点压到 `creep = 0.5 m/s`（`route_pb.h` 的 `PB_END_CREEP`），不会全速冲到表尾。

## 已踩的坑（改动时注意）

- **分隔条不能在 `Load` 里设**：那时 `SplitContainer` 宽度还没定型，会算出越界值，表现是**参数面板整个消失**。
  所以放在 `OnShown` 里，并且配 `Panel2MinSize` + `FixedPanel`。
- **按钮宽度不要写死**：13.5pt 下"开始接收"四个字就要 123 px，写死 84 设计像素（×1.5=126）
  只剩 3 px 余量，看着就像文字被裁。改用 `AutoSize` + `MinimumSize`。
- **`ChannelStore.Append` 前必须先 `Ensure(N)`**：否则 `count` 被夹成 0，一帧也进不去，波形永远空白。
- **横轴用 PC 本地时间**，不用帧里的 `TS` —— 否则丢包会让波形压缩/拉伸。
- 参数数值框的小数位由**步长**决定（步长 0.001 → 3 位）。所以默认值 `0.1548` 会显示成 `0.155`。
  这是显示精度，不是数据被改；拖动滑条时下发的值也是 3 位小数（对增益来说足够）。
- **心跳默认关**：车端当前是「观测」模型，不需要保活。勾上「心跳 100ms」才会周期性发 PING
  （车端 `HOST_ALIVE_MS=600`，100ms 有 6 倍余量）。将来做接管开车时这个开关必须默认开。
